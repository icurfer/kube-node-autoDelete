# 코드 리뷰 & 배포 형상 점검 — 2026-07-31

대상: `kube-node-autodelete` v0.1.0 (chart 0.2.0), 클러스터 `hk8s`

## 0. 배경

"calico 에러의 원인이 이 컨트롤러 아니냐" 는 의심에서 출발한 점검.
**결론: 무관.** calico Degraded 는 `kubemosaic` 의 admission webhook 이 tigera-operator 를
차단해서 발생한 별개 문제다 (진단 문서: `~/infra/hm-k8s/calico-degraded-kubemosaic-webhook.md`).

다만 컨트롤러가 calico 를 건드리는 접점이 실제로 있고, 그 외 개선점도 확인됐다.

## 2. 운영 로그에서 관찰된 실제 동작

GPU 노드 `rtx3060` 정전 이력 — **4회 삭제**:

```
2026-07-15T16:29:42Z  Node NotReady too long → drain & delete   (since 16:27:41 = 2분)
2026-07-15T16:29:42Z  Evicting pod nvidia-cuda-validator-...    namespace: gpu-operator
2026-07-15T16:29:42Z  Evicting pod calico-typha-...             namespace: calico-system
2026-07-15T16:30:12Z  Drain complete: no evictable pods left
2026-07-15T16:30:12Z  Deleting node
```

동일 패턴이 07-20, 07-22, 07-23 반복. 재등록 후에는 GPU taint 복구가 정상 동작:

```
GPU node not ready yet (allocatable empty), waiting for device plugin
GPU taint restored  taint: nvidia.com/gpu=present:NoSchedule
```

## 3. 지적 사항

| # | 위치 | 문제 | 조치안 |
|---|---|---|---|
| 1 | `controllers/node_controller.go:15` | `notReadyGrace = 2 * time.Minute` 컴파일타임 상수. **정상 재부팅도 삭제 대상** — rtx3060 4회 삭제의 직접 원인 | `--not-ready-grace` 플래그 + helm value. 코드 기본값은 2m 유지(호환), 배포값 5~10m |
| 2 | `controllers/pod_utils.go:26` | 보호 네임스페이스가 `kube-system` 하나뿐 → `calico-system/calico-typha`, `gpu-operator` Pod 를 evict. typha PDB(`maxUnavailable=1`, replicas 2) 예산을 죽은 노드 Pod 가 점유 | `--protected-namespaces` 목록화. 기본값 `kube-system,calico-system,tigera-operator,calico-apiserver` |
| 3 | `controllers/drain.go:54` | eviction 실패 시 **즉시 return** → 나머지 Pod eviction 스킵 + reconcile error. PDB 위반(429)도 치명적 에러로 취급 | 전 Pod 시도 후 error aggregate, 429 는 error 대신 requeue |
| 4 | `controllers/drain.go:30` | drain "완료" 판정이 실제 종료 대기가 아님. `filterEvictablePods` 가 `DeletionTimestamp != nil` 을 제외하므로, eviction 요청만 걸리면 다음 회차에 "완료"로 판단 | 의도된 동작이면 함수 주석·README 에 명시. 아니면 실제 종료 대기 필요 |
| 5 | `controllers/node_controller.go:101` | drain 타임아웃 없음 — eviction 이 계속 실패하면 30초 requeue 무한 반복 | 최대 drain 시간 초과 시 강제 Node 삭제 |
| 6 | `helm/values.yaml` | `replicaCount: 1` + `leaderElection.enabled: false` 인데 **worker01 상주, priorityClass 없음**. 이 컨트롤러가 올라간 노드가 죽으면 아무도 노드를 정리하지 못하는 SPOF | control-plane 배치(nodeSelector + toleration) 또는 `priorityClassName: system-cluster-critical` |
| 7 | `controllers/node_logger.go` | `logNodeSummary` 어디서도 호출되지 않는 dead code | 삭제 |
| 8 | `helm/` | metrics `:8080` 이 Service/ServiceMonitor 없이 인증 없이 노출 | Service + ServiceMonitor 추가하거나 metrics 비활성 |
